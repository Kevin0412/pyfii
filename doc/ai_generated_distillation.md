## 退化模式分析

### 车道退化（固定 X 或 Y 范围）

**典型案例：codex_mirror_bloom**

```
d1: X[40,106] (66cm)   Y[51,493] (442cm)   ← X 被锁在 66cm 窄道
d2: X[100,172] (72cm)   Y[156,406] (250cm)   ← X 被锁在 72cm 窄道
d3: X[176,236] (60cm)   Y[167,378] (211cm)   ← X 被锁在 60cm 窄道
d4: X[241,309] (68cm)   Y[160,426] (266cm)
d5: X[308,386] (78cm)   Y[160,389] (229cm)
d6: X[381,461] (80cm)   Y[162,406] (244cm)
d7: X[458,520] (62cm)   Y[58,487] (429cm)    ← X 被锁在 62cm 窄道
```

七架机被等距排列在 X 轴上（40→100→176→241→308→381→458），每架只在自己的窄 X 道内做 Y 向运动。这是"车道编排"的教科书案例——保证了安全（最小距 58cm）但视觉上可预测、单调，一眼看穿套路。

**部分车道：original_flow_field_v5**

```
d2: X[49,168] (119cm)   Y[169,362] (193cm)   ← X 范围偏窄
d4: X[150,420] (270cm)  Y[40,148] (108cm)    ← Y 范围偏窄
d7: X[262,456] (194cm)  Y[381,520] (139cm)   ← Y 范围偏窄
```

flow_field 系列按"场"的设计理念将各机分配到不同空间象限，部分机活动范围偏窄。虽然比 mirror_bloom 好（各机范围 100-270cm vs 60-80cm），但仍有限制动作多样性的倾向。

### 绕圈退化（角度顺序冻结）

original_flow_field_v5 中 6 架机绕场地中心的顺时针排列顺序几乎不变（71 次采样中 68 次顺序相同）。虽然不是严格的一架在中心 + 六架绕圈，但角度排序冻结意味着"绕圈感"很强——各机相对中心的方位角关系始终固定，没有交叉换位或顺序变化。

**检测**：每秒采样各机相对中心的角度排序，若 80% 以上采样点顺序不变，标记。

**修复**：在 phrase 中引入角色交换，打破固定的角度顺序。允许两架机交换方位，或让中心偏移。

### 无退化标记的产物

**gpt55 系列**：四产物共享同一 XY 跨度（477×492），所有机的 X 和 Y 变化范围都在 340-470cm 之间，没有单轴限制。是最均衡的设计。

**original_crosscut_v9**：d6 有轻度车道（X 180cm），其他机 350-430cm。整体可接受。

**original_kinetic_ribbon_v8**：所有机 X 390-450cm、Y 400-450cm，全场覆盖均匀，无车道。

## 动作连贯度

用相邻帧位移变化的标准差（jerk）衡量动作平滑度。jerk 低 = 平滑连续运动，jerk 高 = 突跳/切换多。

| 产物 | jerk 范围 | 运动特征 |
|---|---|---|
| codex_mirror_bloom | 0.8-1.9 | 车道内平滑（因为只在一维运动） |
| original_flow_field_v5 | 2.2-2.3 | 场内平滑 |
| gpt55_phrase_vibe_v3 | 2.3-3.4 | 中高密度切换 |
| original_crosscut_v9 | 3.0-3.8 | 有突跳切段 |
| gpt55_template_motion_v2 | 3.2-4.2 | 模板切换带来突跳 |
| original_kinetic_ribbon_v8 | 3.3-3.5 | 中高密度 |

codex_mirror_bloom 的 jerk 最低（0.8-1.9），不是因为动作设计好，而是因为车道限制使运动维度从 2D 退化到 1D。gpt55_template_motion 的 jerk 最高（3.2-4.2），反映模板切换导致动作不够连续。

## 可蒸馏经验

### 正面

1. **AI 在加速模式下确实能跑通**：所有产物 uf=0，最小距 52-87cm——说明 AI 的 phrase 驱动架构 + 速度求解可以产出可执行的编队。

2. **gpt55_phrase_vibe_v3 是最均衡的设计**：全场覆盖、无车道、中等的 jerk、57cm 安全距离。phrase 驱动 + 动作原语组合是当前最可靠的 AI 生成范式。

3. **original_kinetic_ribbon_v8 空间利用最好**：全场均匀覆盖、无车道、最大最小距（87cm）。连续 ribbon 场适合做平滑大规模运动。

### 需避免

1. **车道退化**：codex_mirror_bloom 是典型反例。每架机 X 锁在 60-80cm 窄道 = 安全但单调。AI agent 应检测到"各机单轴活动范围 < 100cm"时触发重新设计。

2. **模板切换不连贯**：gpt55_template_motion 的 jerk 高，说明模板衔接不够平滑。phrase 之间应有过渡段而非硬切。

3. **安全边界过保守**：gpt55 系列的 XY 跨度完全一致（477×492），说明安全钳制可能过早截断了动作野心。应允许接近场地边界（560×560）的设计。

4. **随机点切换**：`ai_choreo_candidates_60s` 下的 `burst_recompose`、`weave_exchange` 等出现少量未完成（3-85），可能是随机采样点导致路径不可达。

## 与人类设计的差距

| 维度 | 人类（以 dntg 为参照） | AI（以 gpt55_phrase_vibe 为参照） |
|---|---|---|
| 灯光 | 100ms 级数学驱动颜色序列 | 100ms 级 pulse_color 函数（接近） |
| 角色映射 | 每段字典式重新分配 | 每 phrase 有 group_mode（接近） |
| 轨迹多样性 | 复数旋转 + 利萨如 + 镰锤符号 | phrase_point 数学函数（接近） |
| 速度变化 | 每段独立 VelXY/VelZ | 速度求解自动计算步数 |
| 验证闭环 | Fii.save + show | 预验证 + save + read_fii + show |
| **音乐** | **有音乐** | **全部无音乐** |
| 空间叙事 | 主题驱动的空间语言 | 动作原语组合（缺主题约束） |

AI 在编码速度上有优势，但在**动作设计深度**（车道退化、缺乏主题叙事、无音乐理解）上差距明显。当前所有 AI 产物都没有音乐输入。
