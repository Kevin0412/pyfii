# DeepSeek Cannon 开发反思与 Agent 设计启示

## 一、本次开发数据

- 总耗时：约 6 小时（迭代 40+ 轮）
- 最终结果：5 段，0 距离警告，0 动作警告，XY(519,534)
- 设计方法：散布起始 → 独立区域 → 固定 X 分区，全程不绕圈不悬停

## 二、核心教训

### 1. 开发流程：逐段增量，不可全量

**错误**：一次性写出全部 5 段，然后跑测试调参数。导致调试困难，问题定位模糊。

**正确**：
- 先写段1 → 测试通过(0警告) → 再写段2 → ...
- 每段独立验证，确保当前段清洁后再追加下一段
- 前端确定后，后续段依赖前端位置才可靠

### 2. 设计方法：纸面草稿必须先于代码

**错误**：直接在代码里写几何公式，不断改参数试错。

**正确**：
- 先在纸上画出每段的几何图案和无人机位置
- 确认坐标不越界（0-560 XY, 80-250 Z）即可，安全验收交给 pyfii 的 `read_fii` warning
- 不要预设固定安全距离（如>100cm）——这是枷锁，蒸馏已验证
- 然后才写代码

### 3. 悬停/Deactivate 不可取

让某些飞机在整段中不动（悬停），会导致：
- 动作单调，视觉空洞
- 悬停机成为"障碍物"，主动机靠近时触发碰撞警告
- 人类设计(dntg)中所有机始终活动，只是幅度不同

**正确**：所有机始终有有意义的活动。不应出现长时间小范围运动或长时间悬停——两者都是低活动度，效果等同。不同段可以通过队形、角色交换、分区来区分，而非运动幅度的大小。

### 4. 绕圈退化

多个版本中出现"所有机绕同一中心旋转"的设计。蒸馏文档已指出全程绕圈是退化模式（角度排序冻结），但实际编码时仍然会不自觉陷入。

**注意**：1-2 段绕圈是可取的（如高潮段），不可取的是**全程所有段**都在绕圈。

**检测**：如果所有段的目标位置都依赖`2*pi*i/N`这种固定角度公式，就很可能在全程绕圈。

**修复**：绕圈作为局部手段可用，但必须穿插非绕圈段（分区、交换、独立路径）。



### 5. 预验证函数多余

AI 脚本(gpt55)中的`validate_planned_keypoints()`函数是多余的——pyfii 自身的`drone_config`约束已足够保证可执行性。额外添加安全距离常量（如`F400_SAFE_DISTANCE_CM = 70`）不仅多余，还会限制动作设计。

**正确**：信任 pyfii 的约束。事后用`read_fii`和`show(show=False)`做验收。

### 6. 音乐理解不能表面化

**错误**：卡农是"渐进叠加"结构 → 理解为"渐强" → 设计成不断加大动作幅度 → 前期无聊、后期凌乱。

**用户的设计方法**：
- 简单到复杂（不是幅度从小到大，而是队形从简到繁）
- 或动作维持一致，靠**灯光变化**配合渐强
- GPT 的 crosscut_v9 更受认可——phrase-like 设计 + 确定性角色交换

**正确**：动作复杂度/队形密度随音乐递增，而非单纯的位移幅度。或保持动作一致，让灯光承担音乐表达。

### 7. 不了解 pyfii 的硬性限制

反复触发的错误：
- 坐标越界（XY 0-560, Z 80-250 for F400）
- 时间倒退（intime 不能早于当前时间）
- float坐标需手动int()——GPT未遇到此问题，可能是pyfii潜在bug待查
- 段间时间冲突（需留 > 1s 过渡余量）
- `np.mat` 在新 numpy 被移除（需用 pyfii conda 环境）

**正确**：agent 在生成代码前必须检查这些硬性约束。

### 8. 安全与设计的平衡

zero-warning 是可以做到的，但代价是动作幅度受限。本次设计的 XY(519,534) 已经接近全场极限，说明安全与幅度可以兼得——关键是**空间分区**而非限制运动。

## 三、对 Agent 设计的启示

### Agent 应具备的能力

1. **逐段生成与验证**：生成段1 → 运行 read_fii → 0 警告通过 → 生成段2 → ...
2. **纸面草稿能力**：在生成代码前，先输出几何描述（每段各机位置范围、间距计算）
3. **约束知识库**：XY [0,560], Z [80,250], 时间不可倒退, 段间留 1s 余量, 必须用 pyfii conda 环境
4. **退化检测**：生成后自动检查绕圈（角度排序冻结）、车道（单轴范围<150cm）、悬停（某机范围<30cm）
5. **音乐理解升级**：不简单映射"渐强→加大幅度"，应支持队形复杂度、灯光密度、角色交换等多维度响应
6. **不额外加安全常量**：信任 pyfii 默认约束，不定义 SAFE_DISTANCE_CM

### Agent 应避免的行为

1. 一次性输出全部段
2. 使用 deactivate/悬停
3. 让所有机共享同一旋转中心
4. 在代码中写预验证函数
5. 不考虑 pyfii 硬性边界就开始编码

## 四、与 GPT 的对比

GPT crosscut_v9 的优势：
- phrase 骨架清晰（每段有名称、意图）
- 确定性角色交换（不是 random）
- 验证链完整（read_fii + show）
- 空间利用较好

我的设计不足：
- 前期过于保守（段1-3 动作幅度小，视觉单调）
- 段4-5 缺乏设计感（固定 X 分区虽然安全但单调）
- 音乐响应表面化
- 灯光设计简陋（简单的 TurnOnAll/TurnOffAll 交替）
